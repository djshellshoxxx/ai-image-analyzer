Audio / voice forensics

A separate, independent module for speech/audio — upload a file or analyze your microphone live. Runs container/metadata parsing (WAV/BWF/MP3/FLAC/Ogg/Opus/MP4/M4A, plus AIFF/WebM identification), an optional C2PA check, signal-domain acoustic measurements, and a real AASIST-L anti-spoofing ONNX model (~766 KB, MIT-licensed) on overlapping 4-second windows. AASIST-L is trained for speech anti-spoofing specifically — its published accuracy is excellent in-domain (0.99% EER on ASVspoof2019 LA) but drops sharply on unseen conditions (44.45% EER on In-The-Wild, 50.72% on CD-ADD per its model card), so its score is shown as a labeled anti-spoofing signal, never a universal "AI probability." No audio is uploaded anywhere; only the small runtime/model files are fetched into your browser.

How PROVENANCE works

This tool looks for evidence that an image or video was created or edited by generative AI. It never uploads your files anywhere — every check listed below runs inside your browser tab. Only the model-backed detectors you explicitly enable, with a URL you supply, fetch anything from the network (the model weights themselves).

The evidence hierarchy

Not all signals are equally trustworthy. From strongest to weakest:

  • Validated C2PA / Content Credentials — a cryptographically signed manifest. A "Trusted" state is the closest thing to proof this tool can show.
  • Mutable metadata declarations — EXIF/XMP/IPTC fields that say "trainedAlgorithmicMedia" or similar, but aren't cryptographically signed. Easy to fake or strip, but real when present.
  • Neural pixel classifier — a statistical model estimate. Strong when confident, but not proof, and can be wrong on heavily compressed or stylized images.
  • Advanced research modules — spectral, color, bit-plane, JPEG-fingerprint, and similar statistical probes. Almost all of these report score: null deliberately — they're uncalibrated measurements, not probabilities, until you calibrate them against your own real+AI corpus.
  • Circumstantial fingerprints — filename patterns and resolution matches. Free and instant, but only ever a hint, never a verdict on their own.

The final "verdict stamp" on each file only ever uses the first three tiers, in that priority order. The research modules and circumstantial fingerprints are shown for your own review but never automatically escalate a verdict past what real evidence supports.

Batch mode

Upload as many files as you like. Each one runs through every checked method independently. Results are grouped by detected filetype so you can scan a mixed batch quickly. Every card has a "Download JSON" button for that single file, plus an expandable full text report. Once you've analyzed more than one file, a batch-level "Download CSV summary" button appears — one row per file, with the verdict, confidence, and key scores as columns, so you can drop it straight into a spreadsheet.

Supported file types

  • PNG / JPEG / WebP / HEIC / HEIF / AVIF / TIFF — full metadata, C2PA validation, and pixel analysis.
  • GIF — GIF87a/89a header parsing, Application/Comment extension scanning (including embedded XMP), first-frame pixel analysis.
  • BMP — header/structure parsing (BMP rarely carries metadata), pixel analysis via the browser's native decoder.
  • SVG — this is XML text, not raster pixels, so pixel-based modules are not meaningful; the tool instead scans the markup for embedded XMP/RDF metadata, editor signatures (Illustrator, Inkscape, AI vector tools), and viewBox/size attributes.
  • JPEG XL (.jxl) — container box parsing (EXIF/XMP boxes, a "jbrd" box indicating the file was transcoded from an original JPEG). Browser support for actually decoding JXL pixels is inconsistent across browsers as of this build, so pixel-based modules may be unavailable and the tool will say so rather than fail silently.
  • MP4 — ISO-BMFF box scanning (same family as HEIC/AVIF), including a C2PA video-manifest check and a shallow scan for embedded XMP. Pixel-based modules sample a few frames via your browser's video decoder rather than a single still.
  • WebM — format identification and frame-based pixel analysis; deep Matroska/EBML metadata parsing is not implemented, so metadata results will be sparse by design, not by bug.
  • RAW (CR2/NEF/ARW/DNG/ORF/RW2/PEF/RAF) — beta — many RAW formats are TIFF-based, so EXIF (camera make/model/lens/etc.) often parses correctly and is genuinely useful circumstantial evidence against AI origin. Browsers cannot decode RAW sensor data to pixels, so there is no preview image and every pixel-based module (neural classifier, resolution fingerprint, all "advanced" modules) is skipped for these files.

What this tool cannot do

It cannot prove an image is authentic — absence of AI evidence is not evidence of authenticity. It cannot see through a screenshot, a re-compression, or a deliberately stripped file with the same confidence as an untouched original. Treat every result here as one input into your own judgment, not a final answer.
Interpret every evidence class according to what it can actually establish. This tool keeps cryptographic provenance, mutable metadata, neural pixel classification, watermark detection, advanced research signals, and circumstantial fingerprints separate, and never lets a weaker class outrank a stronger one in the verdict shown.
